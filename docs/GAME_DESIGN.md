## 1. ゲーム概要
- ジャンル: 2D ターン制 RPG / ローグライク要素
- 開発: Unity 2023.2.22f1 / C#
- プレイヤーがキャラクターを選び、ダンジョンを進み、敵とのターン制戦闘を繰り返す。
- 中核の面白さ: 敵の行動を読み、狙う部位を決め、部位破壊によって戦況を変える。
- 企画書: `BREAK_TACTICS_10pages.pdf`（リポジトリに置いた場合の参照名。未配置ならユーザーから共有）

## 2. 既存システム（2026-10-19時点の確認情報）
- シーン: Title / Town / Quest
- 戦闘: プレイヤーと敵の1対1、ターン制、通常攻撃、スキル、MP、クールダウン、状態異常
- 部位: 顔 / 手 / 脚 / 腹。腹は破壊不可。本体HPと部位HPを別管理。
- 敵AI: Attacker / Tank / Speed と Tank Boss 専用の行動ルール

- 階層: FloorData を使って敵を設定・出現させる。

## 4. Phase 2 の第一目標（優先度A）
**敵の攻撃予告・部位破壊による妨害**を、まず敵1体・攻撃1種類で実装する。

### 最小のプレイ体験
1. 敵が次に使う行動を確定する。
2. プレイヤーに「次のターン、強力な攻撃」等の予告を表示する。
3. プレイヤーが攻撃対象の部位を選ぶ。
4. 対応する部位を今回の攻撃で破壊した場合、予告済みの特定攻撃を妨害できる。
5. 妨害が成立しなければ、敵が予告どおりの行動を行う。
6. 敵が生存していれば次の行動へ移る。

### 設計上の要件
- 予告用に決定した行動は保持し、実行直前に別の行動をランダム再抽選しない。
- すでに壊れている部位を選び直すだけで、毎ターン妨害が発生することは避ける。
- 敵の死亡、戦闘終了、行動不能、ステータス変化が起きたときの処理を明確にする。
- プレイヤーの追加行動、状態異常、クールダウン、MP不足を含む既存仕様を維持する。
- UIに予告の対象や妨害の成功・失敗を分かりやすく伝える。
- 実装上、敵ターンを変更する前に現行 BattleManager / EnemyAI / BodyPart / EnemyPartsController の流れを確認する。

### 最初の受け入れ条件
- 敵1体が予告を表示し、次の行動がその内容と一致する。
- 指定した部位の新規破壊で、予告攻撃が一度だけ妨害される。
- 部位破壊に失敗すれば予告攻撃が成立する。
- 既存の通常戦闘、ボス戦、勝敗、成長画面、ダンジョン進行を壊さない。
- Unityで手動検証した結果を記録する。

### 実装前にユーザーが最終決定する項目
- 予告する攻撃の種類と対象の敵
- どの部位破壊で、どの攻撃を妨害できるか
- 部位HPや予告までのタイミング、妨害成功時の敵の行動（完全スキップか通常攻撃への差し替えか）
- 予告UIの見た目と表示タイミング
