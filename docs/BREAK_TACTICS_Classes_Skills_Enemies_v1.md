## DEF=0の意味

現在の計算は防御分母にmax(1, DEF)を使うため、0除算にはなりません。一方、DEFを0→4にすると他条件一定ではダメージが概ね半分になります。防御値の小さな増加でも影響が大きいため、攻撃力だけでなく実被ダメージで比較します。[S3]

## バーサーカーの成長との整合

「防御力・魔法防御力が無い」を一貫させ、バーサーカーの恒常DEF/MDEFは0とします。現在の防御1.2倍報酬は0に効果がないので、バーサーカーの候補から除外し、同じ枠をAT1.2倍報酬へ置換します。共通技能による一時的な直接ダメージ軽減は許可します。

> 成長の基本3枠：戦士=最大HP/AT/DEF、魔法使い=現在どおり最大HP/MAG/DEF、バーサーカー=最大HP/AT/最大MP。倍率は既存1.2を維持。最大MP増分だけ現在MPも増加させ、全回復はしません。各枠の職業適合は今回の追加範囲です。

# 戦士：部位破壊で戦術を完成させる

*03 / WARRIOR*

## 固有パッシブ「戦技習得」

| 新規破壊した部位 | 獲得能力（その戦闘中のみ） |
| --- | --- |
| 顔 / Face | 洞察：MPを消費するスキルの必要MPを20%軽減。ceil(元コスト×0.8)、元コストが正なら最低1。元コスト0は0。 |
| 手 / Hand | 武技：以後の直接物理攻撃の算出ダメージを1.15倍。左右どちらでも取得し、2本目では重複しない。 |
| 脚 / Leg | 守勢：以後の敵からの直接物理・魔法ダメージを0.85倍。毒・火傷・反射・自傷には適用しない。 |
| 腹 / Belly | 破壊不可なので獲得なし。既存仕様を維持。 |

既存の顔破壊による敵防御低下、手破壊、脚破壊による2回行動は別途そのまま適用します。戦技習得は戦闘ごとに初期化し、生命吸収等のクエスト報酬は初期化しません。獲得した強化は破壊した攻撃へ遡及せず、次の処理から有効です。

| 固有スキル / ID | P・本体/部位 | MP / CD | 効果 |
| --- | --- | --- | --- |
| 破砕斬 / Warrior_BreakSlash | 110・0.9 / 1.6 | 8 / 1 | 単体物理。火力より部位破壊を優先する基本技。 |
| 守りの一閃 / Warrior_GuardSlash | 95・1.0 / 1.0 | 10 / 2 | 単体物理。命中にかかわらず、行動成立後に敵直接ダメージ25%軽減を得る。次の敵行動終了で失効。 |
| 戦巧斬 / Warrior_TacticalSlash | 150・1.0 / 1.2 | 14 / 3 | 単体物理。取得済み戦技習得の種類数nに応じて直接ダメージ×(1+0.1n)、最大1.3倍。単発。 |

> 「守りの一閃」と共通技能「堅守」の一時ガードは重複乗算せず、強い軽減率を採用します。「守勢」は職業パッシブなのでガードと乗算。反射170%にはどちらも適用しません。

# 魔法使い：高MP消費と部位・属性の選択

*04 / MAGE*

既存のファイヤー、アイス、ヒール、マナチャージ等は削除・弱体化しません。追加する3つは魔法使い専用とし、戦士・バーサーカーは取得・使用できません。共通技能には魔法攻撃を含めず、魔法攻撃を職業の識別点にします。

| 固有スキル / ID | P・本体/部位 | MP / CD | 効果 |
| --- | --- | --- | --- |
| 炎槍・穿破 / Mage_FlamePiercer | 180・0.8 / 2.0 | 24 / 1 | 炎・単体魔法。部位破壊に特化。追加火傷は付けない。 |
| 氷獄・封圧 / Mage_FrostBind | 160・0.9 / 1.2 | 30 / 3 | 氷・単体魔法。命中時、既存のFrozenデータを100%で付与試行する。既存の状態競合ルールは維持。 |
| アーケインバースト / Mage_ArcaneBurst | 360・1.2 / 1.0 | 45 / 3 | 無属性・単体魔法。MPを大きく使う本体撃破用。新規状態異常なし。 |

追加3技は命中1.0・会心不可とします。火力評価は確定クリティカルの既存ファイヤーとの比較が必須です。威力Pは実ダメージそのものではありません。

## 設計意図

炎槍は「本体を倒す前に手を壊す」、氷獄は「既存のAT/MAG低下で被害を抑える」、バーストは「MPを使って撃破を早める」という役割に分けます。高コストを正当化できるかは、現在の確定会心ファイヤーに対する優位点で判断します。

## MP管理

初期MP150なら、バースト3回で135を消費します。既存のMP回復手段を活かしつつ、MP不足時に勝手に通常攻撃へ置き換えず、行動と集中攻撃の記録を消費しない既存ルールを維持します。

> 「魔法使いはMP消費が大きい」は新規魔法のコストで表現します。既存スキルのMPを一括で増やしたり、隠れた職業コスト倍率を追加したりしません。凍結は現在の能力低下であり、新しく行動不能へ変更しません。

# バーサーカー：HPを攻撃資源として扱う

*05 / BERSERKER*

DEF/MDEFは0のままです。高いHP・ATで短期決戦を狙いますが、カウンター170%に高火力を入れる危険は残します。自傷と反射を「通常被ダメージ」へ混ぜず、別の原因として扱います。

| 固有スキル / ID | P・本体/部位 | MP / CD | 効果 |
| --- | --- | --- | --- |
| 裂断 / Berserker_Rend | 160・1.0 / 1.5 | 4 / 1 | 単体物理。高ATを活かして部位を壊す。 |
| 血の代償 / Berserker_BloodPrice | 230・1.25 / 1.0 | 0 / 3 | 単体物理。発動前に最大HPの10%を自傷コストとして支払う。自傷だけでHP0になり得る場合は使用不可。 |
| 不屈の雄叫び / Berserker_WarCry | 自己補助 | 8 / 3 | 最大HPの15%回復。次の直接物理攻撃2回を1.25倍にする。命中・ミスの実行で1回消費し、戦闘終了で破棄。 |

裂断・血の代償は命中1.0、会心可、追加critBonus=0。雄叫びは非攻撃・会心なしです。雄叫びの残回数は再使用時に2へ更新し、加算して貯められません。

## 血の代償の確定ルール

HPコスト=max(1, ceil(最大HP×0.10))。現在HPがコスト以下なら、MP/CD/行動/連続攻撃記録を消費せず拒否。使用可能ならHPコストを先に支払い、ミスでも返金しません。後続の反射による死亡はあり得ます。自傷からカウンターや生命吸収は発火しません。

## 集中攻撃との関係

雄叫びは回復・補助行動として集中攻撃の連続記録をリセットします。血の代償の自傷自体は別行動ではないので、命中して実部位ダメージが出れば集中攻撃の通常の記録を進めます。

> 自傷・回復は現在最大HPを使い、クエスト成長に追従します。0防御を維持したまま、一時的な共通ガードを使う対抗手段は残します。

## 狙い澄ましの消費

使用直後から有効。脚破壊による同一ターンの追加行動でも使用できます。実際の直接攻撃を試みた時点で消費するためミスでも失効。MP不足などで攻撃が成立しなければ消費しません。最終命中率は既存の敵回避を含む式へ+0.15し、最後に0〜1へ制限します。

## 解毒が騎士王を無意味にしない条件

解毒にはMPと1行動を使い、CD4を持たせます。自動解除・永続免疫は付けません。騎士王は現行の解禁・封印・再付与判定に従って毒を再び使えます。3ターン経過で耐えるか、今解除するかを選べます。

# 計算・持続・発動順序の共通契約

*07 / COMBAT CONTRACT*

## 新しい数値は同じ式で評価する

基礎ダメージ=Round(3×sqrt(P×AT/max(1,DEF)))、魔法ではAT/DEFをMAG/MDEFに置換します。既存の会心→部位弱点/耐性→本体/部位倍率の契約を維持します。[S3]

職業・雄叫びによる直接攻撃倍率は本体と部位の分岐前に1回だけ適用。集中攻撃、狙い澄ましは部位側だけへ各1回適用。本体実HP減少量をカウンターの基準にします。新規敵攻撃の本体/部位倍率は全て1.0です。既存の敵SkillExecutorが未使用の倍率フィールドを、既存技能まで一括で有効にしないでください。新規仕様を既存の未使用multiplierフィールドへ無条件に詰めないでください。

| 状況 | 統一ルール |
| --- | --- |
| 行動成立 | 生存・対象・職業・MP・HPコスト・CDをすべて検査してからコストを確定する。失敗した選択は行動扱いにしない。 |
| 命中・ミス | 直接攻撃を実行した場合、MP/HPコスト/CD/次攻撃バフは既存契約に従い1回だけ処理。ミスでも返金しない。 |
| 部位破壊 | 実ダメージ後のjustBrokenで1回だけ反応。生命吸収や戦士パッシブを同じ破壊へ二重発火させない。 |
| 反射 | 敵本体の実HP減少×1.7。敵死亡時は反射なし。回復/自傷/継続ダメージから反射を起こさない。 |
| 新しいガード | 敵の直接ダメージだけを軽減。既存の反射や継続ダメージ式は変えない。ガード同士は強い方、戦士の守勢とは乗算。 |
| 持続 | 追加行動は戦闘ターンを増やさない。ガードは次の敵行動終了、狙い澄ましは次のプレイヤーターン終了で期限管理。 |
| 回復と死亡 | 生命吸収は現行どおり反射より先。既に死亡したプレイヤーを回復で復活させない。毒死亡後に入力受付しない。 |

> 敵からプレイヤーへの魔法/補助効果もSkillExecutorの対象型制約を監査します。設定値を置いただけで未対応効果が動いたことにせず、Player側の受け口・UI・終了時解除まで接続してください。

## 部位と行動

顔破壊で魔力徴収を封印。片手破壊で禁呪光槍を封印し、構え中ならその1行動を中断する。標準の防御低下・命中低下・脚2回行動は別途維持。

## AI優先順位

予約済み光槍の解決 → 使用可能な徴収（対象MP>0） → 使用可能かつ未封印の光槍の構え → 魔弾 → 通常攻撃。構え中の再抽選はしない。MP/CDは実行時のみ支払う。

> 対抗策：MPを守りたければ顔、大技を止めたければ手。新しい状態異常「沈黙」は追加しません。初期配置は2〜3階の候補を想定し、後述の試験Sceneで先に評価します。

# データだけで終わらせず、実際に遊べる接続へ

*12 / PLAYABLE INTEGRATION*

## 3職選択とスキル一覧

Townで戦士・魔法使い・バーサーカーを選べるようにする。選んだPlayerDataがQuestとBattleへ正しく渡ること、HP/MP/攻撃種別/固有技能/表示画像が一致することを確認する。新しい技能は各職3＋共通5を初期解放し、魔法使いの既存技能は維持する。

skillSlotCount=3だけを頼りに技能を登録すると表示漏れが起き得るため、実際のSkillSlotUI数とStartSkillsの整合を調査する。既存スキルパネルをページ送りまたはスクロールで拡張し、全所持スキルへ到達できるようにする。名称・MP・CD・説明をTMPで表示する。

## ボス前回復を3職へ拡張

現在の魔法使い限定のボス前HP/MP全回復は、今回プレイ可能になる全3職へ拡張する。戦闘開始直前に現在最大値へ1回だけ回復し、通常戦での全回復や毎ターン回復はしない。職業差の評価で一職だけ不利にしない。

## 報酬と戦闘中強化を分離

生命吸収・集中攻撃の取得状態はクエスト中に持ち越す。戦士の戦技習得、狙い澄まし、ガード、雄叫びの回数等は戦闘終了で解除する。PlayerData/SkillDataを実行中に書き換えず、ランタイム状態へ保持する。

## 新敵の出現

各新敵にEnemyData・Prefab・部位Collider・独自AIを接続し、まず専用の検証Scene/Editorツールで1体ずつ試す。正常なら既存5階構成の非ボス階へ候補として追加する。既存敵と騎士王は削除せず、ボス階の位置も変えない。

> 出現候補の追加は今回許可された変更です。ただしローカルの階層構成を調べ、適合する階がない場合は通常進行の構造を作り替えず、その割当だけ保留して報告します。新敵をゲーム内で遭遇できないまま「完成」にしません。

## 今回の技能総数

新規プレイヤー技能14（固有9＋共通5）、新規敵技能9、合計23。既存技能を名前変更しただけのものは新規件数に含めません。必要な一時バフは状態異常の新種として数えず、既存の毒・炎・氷のルールを変えません。

# UnityCLIを使う実行条件とモデル設定

*14 / UNITY CLI & MODEL*

## モデルの決定

統合実装の推奨はGPT-6.1 Sol / 極高（xhigh）。新しいデータだけの追加・局所修正なら同モデルの高、相互作用と最終レビューは極高を使用します。今回「パワフル」は採用しません。公式のhigh/xhighは確認できますが、「パワフル」というUI表示を特定のモデル設定と同一視しません。[S6][S7]

## Unity CLIとEditor CLIを区別する

公式Unity CLIでEditorをHTTP操作するUnity Pipeline packageはUnity 6.0以降が前提です。mygame1の確認済みバージョン2023.2.22f1へ、Bridge JustのUnity 6用設定をそのまま持ち込んだり、接続のために無断アップグレードしたりしません。[S5]

まずインストール済みのunityコマンド/独自UnityCLI/既存連携の実体・version・helpを確認します。プロジェクトに対応して既に動く連携があればそれを使い、接続先パスも照合します。Unity Pipelineを前提にした未確認コマンドやポート番号を決め打ちしません。

## 2023.2を維持する検証経路

対応するEditor連携が無ければ、Unity.exeのコマンドラインを使います。-projectPath、-batchmode、-executeMethodでEditorスクリプトを動かし、AssetDatabase/PrefabUtilityでアセット作成・参照検証を行います。Test Frameworkの導入済み版のヘルプに従って-runTests等を使います。[S8][S9]

> 同じプロジェクトをEditorで開いたまま、2つ目のbatchmodeを起動しない。未保存Sceneを強制終了しない。ライセンス認証情報を要求・回避しない。認証/IPC/ロックで実行できなければログを残し、Unity検証未実施と明記します。[S8]

## 証拠として残すもの

CLIの実行ファイルとバージョン、実行コマンド、終了コード、Editor.log、Test Runner XML、スクリーンショット、作成アセット一覧、変更差分。C#外部コンパイルとスタブ試験をUnityでの実行成功に読み替えません。
